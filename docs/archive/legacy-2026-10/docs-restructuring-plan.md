# План реструктуризации документации: сбор материалов и перепись отчётов по трекам

**Цель:** Привести документацию к единому стандарту:
1. В основном отчёте трека (`{track}-report.md`) чётко указан: **выбранный вариант, обоснование, точные цены**.
2. Все исходные материалы (веб-страницы с ценами, PDF котировок, скриншоты, расчёты) сохранены локально в `material/{track_name}/{track_name}/` (например, `material/hardware/hardware/`).
3. Документация переписана «с нуля» на основе заархивированных источников.

Для каждого файла в каждом треке:

- Составить реестр `material/sources-registry.csv` с колонками: `track, source_file, url, type, date_accessed, status (downloaded/failed)`.

### 1.3 Оценка полноты данных
- Сверить с `docs/reports/unknowns-and-open-issues.md` — какие вопросы всё ещё открыты.
- Пометить, где цены/решения основаны на решениях владельца (тег `K2`), а где на открытых источниках (`K1`).

## 2. Создание структуры папок материалов (Фаза 2)

Создать директории:
```
material/
├── hardware/              # исходники по оборудованию
├── economics/             # исходники по экономике
├── certification/         # исходники по сертификации
├── sampling/              # исходники по отбору проб
└── common/                # общие источники (курсы валют, общие законы)
```

Внутри каждого `material/{track}/` создавать подпапки по типам материалов:
- `prices/` — цены: котировки поставщиков, листинги, прайсы, расчёты доставки/таможни
- `documents/` — нормативные документы: законы, правилники, стандарты (PDF, HTML)
- `certificates/` — сертификаты, протоколы испытаний, аккредитации лабораторий
- `calculations/` — внутренние расчёты: таблицы Excel/CSV, скрипты, промежуточные данные
- `correspondence/` — переписка: письма в органы, ответы, протоколы встреч
- `web-archive/` — сохранённые веб-страницы (HTML/MHTML) для источников, не входящих в категории выше

## 3. Загрузка и архивация источников (Фаза 3)

### 3.1 Инструменты
- `wget` / `curl` для статических страниц.
- `single-file` (npm) или `monolith` для сохранения полных веб-страниц с ресурсами.
- `pandoc` для конвертации HTML → Markdown (опционально).
- Скрипт `scripts/archive_sources.py` для автоматизации по реестру.

### 3.2 Процедура для каждого источника
1. Скачать исходник в соответствующую подпапку `material/{track}/{category}/` (например, `material/hardware/prices/`).
2. Именовать файл: `{source_id}_{date}_{short_description}.{ext}` (например, `HW-01_2026-10-10_RO-block_Alibaba.html`).
3. В реестре обновить `status=downloaded`, добавить `local_path`.
3. Для критичных источников (цены, законы) сделать также PDF-принт (`wkhtmltopdf`).

### 3.3 Верификация
- Проверить, что все ссылки из реестра скачаны.
- Для недоступных ссылок — пометить `failed`, найти альтернативу или оставить как «не найдено» в отчёте.

## 4. Перепись основных отчётов треков (Фаза 4)

### 4.1 Шаблон нового `{track}-report.md`
```markdown
# {Track} Report

## 1. Выбранный вариант
- **Вариант:** [название/описание]
- **Дата решения:** YYYY-MM-DD
- **Решение владельца:** ID (например, 0031)

## 2. Обоснование выбора
- Ключевые критерии сравнения (таблица).
- Почему отвергнуты альтернативы.
- Ссылки на локальные материалы: `material/{track}/prices/...`, `material/{track}/documents/...`.

## 3. Точные цены и расчёты
| Позиция | Значение | Единица | Источник (локальный файл) | Примечание |
|---------|----------|---------|---------------------------|------------|
| ...     | ...      | ...     | `material/.../file.pdf`   | ...        |

## 4. Неизвестные / открытые вопросы
- Список ссылок на `docs/reports/unknowns-and-open-issues.md` (ID EC-XX, HW-XX и т.д.).

## 5. Приложения
- Полный список архивированных источников (из реестра).
```

### 4.2 Работа по каждому треку
1. **Hardware** (`hardware-report.md`):
   - Выбрана конфигурация: 4 модели (помещение/улица × стандарт/усиленная), бак 20–40 л, нагрев только уличные, камера во всех, автоблокировка.
   - Цены: по позициям из котировок (пока 1 из 27 найдена). Нужно дождаться RFQ.
   - Материалы: котировки поставщиков, технические каталоги, расчёты бака/нагрева.

2. **Economics** (`economics-report.md`):
   - Вариант закупки: «покупаем готовое» (решение 0031, условно).
   - Цена: 50 RSD/5л (решение 0004). Door-to-door цена аппарата — диапазон по найденным позициям (0,5–1,3 тыс. EUR морем, 1,2–2,9 тыс. EUR авиа).
   - Финансовая модель: формулы в `financial-model.md`, сценарии в `pilot-scenarios.md`.
   - Материалы: листинги FOB, ставки фрахта, тарифы BVK, налоговые коды.

3. **Certification** (`certification-report.md`):
   - Путь: «покупаем» для пилота (решение 0040), «производим» — от ~20 точек.
   - Карта сертификатов/разрешений с органами, сроками, ценами (где известны).
   - Чек-лист допуска (14 пунктов).
   - Материалы: тексты законов (PDF), ответы органов, прайсы лабораторий.

4. **Sampling** (`sampling-report.md`):
   - Стандартная конфигурация проб, программа (показатели, частота, объём, тара).
   - Правило выборки для N точек.
   - Стоимость и логистика.
   - Материалы: прайсы лабораторий, протоколы отбора, методики.

### 4.3 Обновление перекрёстных ссылок
- В каждом отчёте заменять внешние URL на локальные пути `material/...`.
- В `docs/reports/final-report.md` и `docs/reports/problems-and-options.md` обновить ссылки на новые отчёты.

## 6. Установление процесса поддержки (Фаза 6)

### 6.1 Правила добавления новых данных
1. Любая новая цена/норматив → сначала скачивается в `material/{track}/` (в соответствующую подпапку: `prices/`, `documents/`, `certificates/` и т.д.).
2. В отчёт добавляется строка с ссылкой на локальный файл.
3. Реестр `material/sources-registry.csv` обновляется.

### 6.2 Регулярный аудит
- Раз в месяц: запуск скрипта проверки доступности исходных URL (перескачивание при изменении).
- Перед каждым крупным решением — сверить, что все использованные источники заархивированы.

### 6.3 Автоматизация
- Скрипт `scripts/update_materials.py`: по реестру качает новые версии, сравнивает хеши, сообщает об изменениях.
- CI-проверка: при коммите в `docs/*/report.md` проверять, что все cités источники существуют в `material/`.

## 8. Критерии приёмки

1. В каждом `{track}-report.md` есть раздел «Выбранный вариант», «Обоснование», «Точные цены» с локальными ссылками.
2. Все внешние ссылки из старых версий документов либо заархивированы в `material/`, либо помечены как «недоступно» с записью в `unknowns-and-open-issues.md`.
3. `pipeline/verify.py` проходит без ошибок (кодировка, язык, классификация строк, наличие источников).
4. Реестр `material/sources-registry.csv` полный и актуален.
5. Документирован процесс (`docs/process/materials-management.md`) для команды.

## 9. Риски и митигация

| Риск | Митигация |
|------|-----------|
| Источники исчезают (404, изменение цен) | Ежедневная/недельная архивация критических URL; используем `single-file` для полного снапшота. |
| Большой объём ручной работы по скачиванию PDF/страниц с авторизацией | Приоритизировать только источники, используемые в отчётах; остальные — по мере необходимости. |
| Несоответствие старых решений новым данным | При переписи отчётов явно фиксировать: «Ранее считалось X, теперь по источнику Y установлено Z». |
| Потеря контекста при переносе | Сохранять оригинальные файлы в `docs/archive/pre-restructuring-2026-10-10/`. |

## 10. Начало работы

**Первый шаг:** запустить скрипт извлечения ссылок из текущих markdown-файлов и сгенерировать `material/sources-registry.csv`.

Пример команды (псевдокод):
```bash
python3 scripts/extract_urls.py --input docs/hardware --output material/sources-registry.csv --track hardware
# повторить для economics, certification, sampling
```

Затем создать структуру папок и начать загрузку.
