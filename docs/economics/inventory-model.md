# Модель запаса с учётом сроков поставки

Сгенерировано `pipeline/inventory.py` (`python3 pipeline/inventory.py` из корня репозитория). Метки: «не найдено» — вход неизвестен (ID в `docs/reports/unknowns-and-open-issues.md`); параметры метода — предложение методики, не факт. Прежние таблицы позиций, точек заказа и капитала в запасе для 1/5/20 аппаратов удалены: они опирались на выдуманные цены, интервалы замены, отказы и сроки поставки.

## 1. Формулы

Обозначения: N — число аппаратов, d — суточный расход, L — срок поставки (сутки), SS — страховой запас, ROP — точка заказа, Q — размер партии, S — позиция запаса.

- Расход расходника: d = N × k / T, где k — штук на аппарат, T — интервал замены, сутки.
- Расход по отказам: d = N × k × r / 365, где r — доля отказов в год.
- **Позиция запаса** S = на складе + в пути.
- **Точка заказа** ROP = d × L + SS. Расходник: SS = d × max(7 сут, 25% × L). Позиция по отказам: ROP — 95%-квантиль распределения Пуассона со средним d × L. Числа 7 сут, 25%, 95% — предложение методики, владельцу утвердить.
- Критичные позиции (мембрана, УФ, насос, платёжный модуль): ROP не меньше 1 шт. Обоснование: простой точки стоит p × N_день рублей выручки в сутки (p = 10 RSD/л по решению владельца; N — объём, не найден).
- **Правило заказа:** когда S <= ROP, заказать партию Q. Сравнивается позиция (склад + в пути), а не остаток на складе.
- **Партия** Q = max(MOQ, d × 90 сут), не больше 80% от d × срок годности (предложение методики).
- Запас на старте: расходник — ROP + Q; запчасть по отказам — ROP (при ROP > 0 не меньше MOQ).

Разбор (для условных чисел):
- Первый заказ — сутки 0 (придёт на сутки 8); второй — сутки 4, то есть **до прихода первой** партии: ROP растёт вместе с парком, позиция (склад + в пути) снова опускается до ROP.
- Правило не требует ждать прихода первой партии: заказ определяется позицией и ROP, пересчитанной на текущий парк.
- Минимальный остаток на конец суток: -0.3 шт. — кратковременный дефицит перед приходом первой партии: парк вырос быстрее, чем успел вырасти заказ. Дефицит исчезает при стартовом остатке 5 шт. — иллюстрация вывода: при быстрой раскатке стартовый запас считать по конечному парку.
- Шаблон для своих данных: изменить `ramp`, `lead`, `lot` в `simulate()` и позиции в `PARTS`.
